# 农牧投蓝莓系统 · 后台交互原型

**在线预览：** [GitHub Pages](https://fenlinone.github.io/nongmutou-admin/)（首次部署完成后可用）

**离线使用：直接双击打开 [delivery/index.html](delivery/index.html)。** 无需安装依赖或启动服务器，页面脚本、样式、图标与品牌图片均内嵌。

也可直接双击项目根目录的 `index.html`，它会自动打开 `delivery/index.html`；通过开发服务器访问时仍加载开发源码。

参考来源：[Figma 采摘称重页面（68:153）](https://www.figma.com/design/SRlvhYqklKaZBHRZIwf1bR?node-id=68-153)。该节点为整页栅格图片，因此使用实际组件重建布局与交互，品牌区域保留原始图像。

## 可演示交互

- 逐桶明细与工人产量汇总切换，支持浏览器前进、后退。
- 日期、工人姓名/工号、大棚、班组、品种、果径、等级、记录状态组合查询；重置和空结果展示。
- 分页、每页条数、跳页、勾选记录、列显隐和恢复默认。
- 查看称重记录、关联筐称重明细及工人产量详情。
- 导出当前筛选结果为 CSV；勾选明细时只导出选中记录。
- 侧栏展开收起、菜单分组展开收起、消息和用户信息展示。

## 演示范围

- 当前包含业务概览、采摘称重、原果管理、成品管理、工人管理与果品资料；其余菜单保留导航和范围说明。
- 1,860 条数据均为模拟数据。首屏八条与参考图一致，其他记录用于演示查询、分页与汇总。
- 仅有效记录计入工人产量，作废记录的有效产量为零。汇总与明细共用筛选结果。
- 表格默认每页 20 条，表体内部滚动；首屏显示八条，保持参考图的信息密度。
- 筛选和列设置仅在当前会话生效，刷新恢复初始状态。无后端、真实鉴权或在线服务。

## 成品管理演示

从左侧「成品管理」进入，包含成品库存、入库记录、出库记录三个页签。托盘管理已合并到成品库存，通过「当前在库 / 全部托盘」切换查看当前库存箱和历史箱。成品库存按箱展示，一行一箱；箱码定位单箱，托盘码可筛出该托所有关联箱，点击箱码或托盘码可查看详情。汇总和导出按箱级记录统计。

- **组托入库**：点击模拟箱码或输入箱码加入清单，选择仓库、核对箱数后确认；确认前不增加库存。重复码、已组托箱和混品种/包装规格会被拦截。
- **成品出库**：按仓库选择整托当前在库箱或单独整箱；扫码、整托和整箱选择按箱去重。确认后扣账并生成新的出库批次与出库单。
- **整批恢复**：从原出库记录发起，填写原因并确认全部货物回仓；整批只能恢复一次，保留原出库数量和单据，再次发货生成新批次。
- **查询与详情**：支持完整箱码/托盘码查询、箱码反查历史托盘、仓库/品种/果径/等级/规格/日期及恢复状态筛选、分页、列设置和 CSV 导出；箱、托盘、流水和出库单详情可相互查看。
- **数据联动**：三个页签、箱/托盘详情及业务概览中的成品库存、期间指标和图表共用会话数据，切换菜单不会丢失；刷新恢复初始数据。概览其余业务仍使用原有模拟数据。

演示数据：初始成品库存 **20 箱 / 32.50 kg**，10 条历史托盘记录（其中 9 托当前有库存），首次组托入库共 30 箱，原出库共 13 箱，其中已恢复 3 箱；另有 12 个已贴码待组托箱。

| 演示码 | 用途 |
| --- | --- |
| `CP20261020000001`～`CP20261020000008` | 同品种同规格，可组同一托盘 |
| `CP20261020000009`～`CP20261020000010` | 蓝莓2号，用于校验混品种 |
| `CP20261020000011`～`CP20261020000012` | 蓝莓1号、不同包装规格，用于校验混规格 |
| `CP20261015000001` | 已入库箱，用于校验重复组托 |
| `TP202610160005` | 当前在库为零的历史托盘 |

**演示边界**：屏幕报数和托盘标签预览可用，未连接扫码硬件、音响或实体打印机。出库单为演示版；收货、运输字段和正式版式待确认。按原组托记录展示关联箱的库存状态，不执行托盘解绑、重组托或入库撤销；拆零、恢复后的现场托盘归属仍待确认。本次出库演示按仓库分别办理，不定义跨仓同批规则。

## 开发

运行环境：Node.js 22.12+ 或 24，pnpm。核心依赖：React 19、TypeScript 5、Ant Design 6、ProComponents 2、Vite、vite-plugin-singlefile。具体安装版本见 `pnpm-lock.yaml`。

```bash
pnpm install
pnpm dev
pnpm build
```

`pnpm build` 先执行 TypeScript 类型检查，再重新生成 `delivery/index.html`。

| 目录 | 内容 |
| --- | --- |
| `src/components/` | 侧栏框架、筛选区 |
| `src/pages/WeighingPage.tsx` | 明细、汇总、弹窗与导出 |
| `src/data.ts` | 演示记录、组合筛选、有效产量汇总 |
| `src/styles/` | 技能全局规范与 Figma 视觉映射 |
| `delivery/index.html` | 离线单文件交付物 |
| `reference/` | 浏览器截图与验证报告 |
| `scripts/verify.mjs` | 使用本机 Chrome 和工作区 Playwright 的离线场景验证 |

## 验证

`scripts/verify.mjs` 通过 `file://` 直接打开最终 HTML，并将浏览器网络设为离线，检查主要交互、CSV 实际内容、汇总计算、Hash 路由、资源完整性和横向溢出。此脚本的 Playwright 路径为当前工作区运行时路径；换机器执行时需调整导入位置与 Chrome 路径。

```bash
node scripts/verify.mjs
```

关键计算案例：筛选 2026-10-16 后应有 8 条记录，7 条有效记录共 **37.00 kg**；张三有效产量 **12.10 kg**，陈七作废记录有效产量 **0.00 kg**。

成品管理验证（需要当前机器的 Node.js 与 Chrome）：

```bash
node scripts/verify-finished-ledger.mjs
node scripts/verify-finished-goods.mjs
```

账本验证覆盖箱数与重量守恒、重复操作和恢复后再次发货；浏览器验证直接断网打开交付 HTML，覆盖三个页签和组托—出库—恢复全流程。结果保存到 `reference/成品管理-验证报告.json`，截图保存在 `reference/`。
